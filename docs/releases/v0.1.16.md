# Pathmark v0.1.16

Pathmark v0.1.16 gives Claude Code the same automatic integration Codex and Gemini CLI already had, brings Claude Code's built-in memory into the shared store, and makes Pathmark legible to hosts that defer tool schemas.

## Claude Code integration

- `pathmark setup claude-code` prints `claude mcp add --scope user ...`; the previous command registered Pathmark only for the current directory.
- It also prints a `hooks` block for `~/.claude/settings.json`: SessionStart (startup, resume, clear, compact, fork) injects the approved intent snapshot, UserPromptSubmit recalls and captures the prompt, PostToolUse captures compact redacted tool activity, and Stop captures the final reply.
- `pathmark hook <event> --client=claude-code` keeps the `mcp__pathmark__*` tool names Claude Code uses. The Stop hook reads `last_assistant_message` and falls back to the transcript tail on older Claude Code versions, skipping sidechain (subagent) turns.

## Native memory import

- `pathmark import-native claude-code [--root=DIR] [--project=SLUG] [--namespace=NAME] [--dry-run]` imports `~/.claude/projects/*/memory/*.md` (honoring `CLAUDE_CONFIG_DIR`) as raw evidence tagged `claude-code-memory` and `memory-type:<type>`.
- Each project's real directory is recovered from a session transcript, or by matching the directory slug against the filesystem, so imports carry the same `project:` and `workspace:` tags as captured sessions.
- Re-running is a sync: new files are added, edited files update in place with history, unchanged files are skipped, and records deleted in Pathmark are never resurrected. Imports are evidence, never conclusions, so the approval gate is unchanged.

## MCP host compatibility

- The server now sends MCP `instructions` describing when to recall, what to save, and that memory is untrusted data. Hosts that defer tool schemas behind tool search still surface these instructions to the model.
- All 25 tools declare MCP annotations. Recall, search, and diagnostics are read-only; `purge_memory`, `compact_memory`, and `delete_memory` are destructive; `ask_memory`, `chat`, and `consolidate_memory` report `openWorldHint` only when synthesis leaves the machine.

## Claude synthesis preset

- `PATHMARK_SYNTHESIS_PROVIDER=claude` (with optional `PATHMARK_CLAUDE_COMMAND` and `PATHMARK_CLAUDE_MODEL`) synthesizes through the Claude CLI's own authentication, including subscription login.
- The process runs with no tools, no MCP servers, hooks disabled, no saved session, a fixed isolated working directory, and no `PATHMARK_*` environment variables. Failures report the CLI's own error message instead of an empty one.

## Dependency security

- Update transitive `hono` from 4.13.2 to 4.13.9, the patched release for three moderate-severity advisories. Pathmark serves MCP over stdio only, so these HTTP-layer issues were not reachable, but the published lock no longer carries them.

## Fixes

- The memory-quality evaluation used a fixed fixture date that aged out of the 30-day raw-recall window, turning the suite red on an unchanged `main`; fixtures are now relative to the current date.
- Compatibility docs no longer pin an outdated Codex model.

## Verification

- A new wire-level suite connects a real MCP client over stdio to check server instructions and annotations on every tool, drives the Claude Code hook paths, runs the Claude preset against a stub CLI to verify isolation flags and environment stripping, and covers native import sync, redaction, slug resolution, and deletion handling.
- Full TypeScript build, runtime suite, memory-quality evaluation, ESLint, and coverage thresholds.
