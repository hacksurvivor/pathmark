# Pathmark v0.1.5

Hardening and scale release.

## Reliability and performance

- Added a derived SQLite search index while keeping `memory.jsonl` as the canonical, inspectable store.
- Search, record counts, duplicate checks, and Codex prompt recall no longer parse the complete JSONL file on every call.
- Invalid JSONL records are isolated from search and reported through `pathmark codex status` instead of breaking the store.
- The legacy importer now uses the same write lock and append path as live Pathmark writers.

## Recall quality

- Prompt tokenization now supports Unicode, including Russian and CJK text.
- Added CJK bigram/trigram indexing so short terms remain searchable.

## Security and configuration safety

- Redacts standalone PEM private keys and unterminated quoted secret assignments.
- Codex-backed synthesis sends memory through stdin, runs in an empty temporary workspace, ignores project rules, and receives a minimal environment.
- Memory records are explicitly treated as untrusted data in synthesis prompts.
- Codex installation preserves unmanaged `mcp_servers.pathmark` configuration and backs up `config.toml` before changes.

## Engineering and release controls

- Added regression tests for store corruption, Unicode recall, locking, config preservation, redaction, and every synthesis provider.
- Added ESLint and coverage reporting with enforced minimums.
- CI now tests Node.js 22 and 24; the supported runtime is Node.js 22.5 or newer.
- npm publishing is tag-only, validates release metadata, uses the protected `npm` environment, and dry-runs the package before publishing.
