# Pathmark v0.1.11

Pathmark v0.1.11 makes the product intent-first: code remains authoritative for implementation, while Pathmark carries approved decisions, preferences, constraints, evidence, and provenance across agents.

## What's New

### Proactive intent instead of passive capture

- Recall approved workspace and project conclusions before raw session history.
- Inject at most two fresh, high-confidence scoped raw records when no approved conclusion matches.
- Keep the full raw archive explicitly searchable after it ages out of automatic recall.
- Never inject raw cross-project history automatically.

### Evidence-backed consolidation

- Add `consolidate_memory` and `pathmark consolidate` to prepare bounded unsynthesized user/assistant evidence batches.
- Support client-side extraction by the MCP host and optional Codex CLI, command, or OpenAI-compatible server synthesis.
- Attach exact `evidenceIds` to derived conclusions.
- Move the disposable derived index to `memory.index.v5.sqlite` so older running processes cannot strip new provenance fields from indexed representations during a rolling restart.
- Stage generated candidates as pending approval; never auto-approve extracted intent.
- Nudge Codex at session start when a scoped raw backlog has crossed the configurable consolidation threshold.

### Chat with memory

- Make MCP `chat` and `ask_memory` conclusion-first with an explicit raw-evidence fallback.
- Add `pathmark chat "question"` for the same workflow from the CLI.
- Return retrieval mode, context, exact used-memory metadata, and a clear next step when synthesis remains client-side.

### Measurable memory value

- Add read-only `pathmark audit` and `audit_memory` reporting for capture-to-recall behavior, unused records, age at recall, exact duplicates, stale raw hits, and evidence-to-conclusion coverage.
- Report retrieval precision as unlabeled until user relevance labels exist.

### Release visibility

- Add a prominent README “What's New” section, a live npm version badge, and a top-level changelog.

### Official MCP Registry readiness

- Add the stable Registry name `io.github.hacksurvivor/pathmark` and schema-linked `server.json` metadata for the public npm stdio package.
- Verify package, MCP server, citation, CodeMeta, and Registry versions together before release.
- Add a separate manual GitHub OIDC publication workflow with exact confirmation, npm verification, Registry validation, and a checksum-pinned publisher binary.

## Verification

- Read-only live-store audit and consolidation preview before installation.
