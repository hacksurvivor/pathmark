# Pathmark v0.2.0

Pathmark v0.2.0 consolidates memory on its own, without an agent or a person in the loop for every conclusion. It also keeps two copies of a store in step, so approvals and deletes made on one machine reach the other.

## Why

Capture worked, but nothing turned captured sessions into conclusions unless an agent stopped to do it and a person approved every result. Real stores ended up with thousands of raw snippets and a handful of approved conclusions, so recall had little worth returning. Syncing two machines with export and import also lost information: import only adds records, so an approval, a correction or a delete made on one machine never reached the other, and deleted records came back.

## `pathmark dream`

- Modelled on Anthropic's two dream designs: Claude Code's Auto Dream (orient on existing memory, gather new signal, merge it in, prune) and Managed Agents dreaming (a bounded batch of sessions in, a reviewable result out, duplicates merged, the latest value winning).
- Runs unattended with a server-side synthesis provider (`claude`, `codex`, `command` or `openai-compatible`). It is a preview unless `--apply` is present.
- Each run takes projects with at least two unreviewed user/assistant records from the last 30 days, smallest first, and reads bounded batches alongside the project's existing conclusions. Candidates may add a conclusion or replace one (`supersedes`). Candidates that cite evidence outside the batch, rate below 0.8, or look like instructions are dropped.
- Reviewed evidence ids are stored in `dream-state.json`, so evidence that held nothing worth keeping is not read again. Ids of records that no longer exist are pruned.
- `dream-digest.md` lists what was added, replaced and left for review, with the replaced text.
- Optional `--retention-days` ends the run with a compaction that keeps tombstones for `--tombstone-days` (default 30).

## Auto-approval

- Off by default. `--auto-approve` or `PATHMARK_DREAM_AUTO_APPROVE=on` approves a conclusion only when it cites at least one record tagged `role-user` (the user's own words) and the model rates it 0.9 or higher. The approval records `decidedBy: "pathmark dream"`.
- A conclusion resting only on an agent's reply stays pending. A proposal that would replace an approved conclusion without the user's words is staged with `supersedes`. Approving it retires the old conclusion, and until then the old one stays in recall.

## Merge sync

- `pathmark import FILE --merge` takes full records (export with `--include-deleted`). New ids are added as they are, tombstones included. For an id both copies hold, the version with the later `updatedAt` wins. Repeating a merge changes nothing.

## Retention

- `--retention-days` and `PATHMARK_RETENTION_DAYS` now expire only automatic capture (raw session records and activity). Memories saved on purpose and conclusions stay, and so does any evidence a live conclusion cites, which also survives deduplication.
- `compact --tombstone-days=N` keeps deleted and superseded records for N days instead of dropping them, so a merge can carry the delete.

## Verification

- New `scripts/test-dream.mjs` checks that a preview writes nothing, that auto-approval needs the user's words and confidence 0.9+, and that it is off by default. It checks that contradicted conclusions are replaced with history kept, that an agent's claim never replaces an approved conclusion without review, and that reviewed evidence is not read again. It also covers merge (approvals and deletes carried, an older version never wins, repeat-safe) and retention (cited evidence, saved memories and recent tombstones kept).
- `scripts/test-consolidate.mjs` pins the clock for its recall check: its fixtures are dated August 2026 and recall looks back 90 days, so the test had started failing on the calendar alone.
- Trial on a copy of a real store with Claude synthesis: 40 records from one project became seven conclusions in 43 seconds, three of them grounded in the user's words.
- Full TypeScript build, runtime suite, memory-quality evaluation and ESLint.
