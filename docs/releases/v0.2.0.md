# Pathmark v0.2.0

Pathmark v0.2.0 consolidates memory on its own, without an agent or a person in the loop for every conclusion. It also keeps two copies of a store in step, so approvals and deletes made on one machine reach the other.

## Why

Capture worked, but nothing turned captured sessions into conclusions unless an agent stopped to do it and a person approved every result. Real stores ended up with thousands of raw snippets and a handful of approved conclusions, so recall had little worth returning. Syncing two machines with export and import also lost information: import only adds records, so an approval, a correction or a delete made on one machine never reached the other, and deleted records came back.

## `pathmark dream`

- Modelled on Anthropic's two dream designs: Claude Code's Auto Dream (orient on existing memory, gather new signal, merge it in, prune) and Managed Agents dreaming (a bounded batch of sessions in, a reviewable result out, duplicates merged, the latest value winning).
- Runs unattended with a server-side synthesis provider (`claude`, `codex`, `command` or `openai-compatible`). It is a preview unless `--apply` is present.
- Each run takes projects with at least two unreviewed user/assistant records from the last 30 days, smallest first, and reads bounded batches alongside the project's existing conclusions. Candidates may add a conclusion or replace one (`supersedes`). A candidate is dropped if even one citation is outside the batch, if it rates below 0.8, or if it looks like an instruction. A namespace is its own scope. `project-aliases.json` in the store directory maps folder names (worktrees, renamed checkouts) to the project name conclusions use.
- Reviewed evidence ids are stored in `dream-state.json`, so evidence that held nothing worth keeping is not read again. Ids of records that no longer exist are pruned.
- A reply that isn't valid dream JSON, a synthesis error or a failed verification leaves the whole batch unwritten and queued for a retry: retried first next time, even below the minimum or outside the day window, and given up after 7 days. Compaction waits while retries are queued, and the command exits with status 1.
- `dream-digest.md` lists what was added, replaced and left for review, with the replaced text.
- Optional `--retention-days` ends the run with a compaction that keeps tombstones for `--tombstone-days` (default 30).

## Auto-approval

- Off by default. `--auto-approve` or `PATHMARK_DREAM_AUTO_APPROVE=on` approves a conclusion only when it cites a prompt the capture hooks recorded (`role-user` plus `codex-raw`), the model rates it 0.9 or higher, and a second, narrow model call confirms the cited words state the claim. The approval is written in one step and records `decidedBy: "pathmark dream"`.
- MCP write tools (`remember`, `update_memory`, `supersede_memory`) now drop the capture markers `codex-raw`, `codex-session` and `immediate-prompt`, so an agent can't make its own text look like the user's words. Editing a captured record's text drops those markers too.
- A conclusion resting only on an agent's reply stays pending. The dream never retires a pending proposal itself (the user may be approving it on another machine): a candidate that would replace one is filed next to it for review. Right before an approval is written, the cited prompts are read again and must be unchanged, and a prompt whose text was ever edited never counts as the user's words. A proposal that would replace an approved conclusion without the user's words is staged with `supersedes`. Approving it retires the old conclusion, and until then the old one stays in recall. Before replacing anything the dream reads the conclusion's current status under the store's write lock, so an approval that lands during the run is never overridden. It also checks the exact revision the model saw: a conclusion edited or replaced meanwhile (by a sync or a person) is never replaced on the stale view, and the candidate waits for review.

## Merge sync

- `pathmark import FILE --merge` takes full records (export with `--include-deleted`). Every record is validated and normalized by the store's own reader before anything is written (approval tags are recomputed, unsafe text is quarantined), and one invalid record aborts the merge. New ids are added as they are, tombstones included. For an id both copies hold, the later `updatedAt` wins, and equal instants resolve the same way on every copy. Repeating a merge changes nothing.
- Run `dream` on one machine only. Two copies that both replace the same conclusion before syncing would keep both replacements.

## Retention

- `--retention-days` and `PATHMARK_RETENTION_DAYS` now expire only automatic capture (raw session records and activity). Memories saved on purpose and conclusions stay, and so does any evidence a live conclusion cites, which also survives deduplication and explicit expiry.
- `compact --tombstone-days=N` keeps deleted and superseded records for N days instead of dropping them, so a merge can carry the delete. Tombstones are never deduplicated.

## Verification

- New `scripts/test-dream.mjs` checks that a preview changes no records, that auto-approval needs the user's words and confidence 0.9+, and that it is off by default. It checks that contradicted conclusions are replaced with history kept, that an agent's claim never replaces an approved conclusion without review, and that reviewed evidence is not read again. It also covers merge (approvals and deletes carried, an older version never wins, repeat-safe) and retention (cited evidence, saved memories and recent tombstones kept).
- `scripts/test-consolidate.mjs` pins the clock for its recall check: its fixtures are dated August 2026 and recall looks back 90 days, so the test had started failing on the calendar alone.
- Trial on a copy of a real store with Claude synthesis: 40 records from one project became seven conclusions in 43 seconds, three of them grounded in the user's words.
- Full TypeScript build, runtime suite, memory-quality evaluation and ESLint.
