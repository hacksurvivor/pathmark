# Pathmark v0.2.1

Pathmark v0.2.1 fixes the session-start memory snapshot on large stores and makes capture use project aliases.

## Fixes

- The session-start snapshot fetched the 500 newest approved conclusions across the whole store and then filtered them by project. In a store with thousands of conclusions the current project's facts were usually not among them, so the snapshot came back empty apart from a "[truncated]" line. Scoped conclusions are now fetched by tag, and a snapshot with nothing to show is left out.
- `project-aliases.json` in the store directory maps folder names (worktrees, renamed checkouts) to the project name conclusions use. Capture still tags records with the folder name, so raw recall never crosses checkouts. The session snapshot looks up both the folder name and the canonical name, and `pathmark dream` groups evidence under the canonical name. Edits to the file are picked up without a restart.
- A namespace in scope now narrows every snapshot lookup, including the one the session-start hooks make with `PATHMARK_NAMESPACE`, so scoped facts never cross namespaces. Folder-name and canonical matches compete by recency for the snapshot budget.
- When `pathmark dream` replaces a conclusion, the replacement keeps the old one's `wiki:`, `wiki-private:` and `section:` tags. Approving a replacement without explicit tags adopts the original's current placement, read under the write lock, so a move made after the proposal was written is never undone; a reviewer's explicit tags win. Approving a proposal whose original is no longer live is refused, so it gets a fresh review.

## Verification

- New checks in `scripts/test-dream.mjs`: a project's fact appears in the snapshot with 600 newer conclusions from another project in the store, the snapshot finds canonical conclusions through an alias while capture keeps the folder tag, a namespace never leaks into another's snapshot, a folder named `constructor` stays itself, and approval keeps a placement changed after the proposal.
- `scripts/test-codex-adapter.mjs` now expects no snapshot block when there are no approved conclusions.
- Full TypeScript build, runtime suite, memory-quality evaluation and ESLint.
