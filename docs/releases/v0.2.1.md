# Pathmark v0.2.1

Pathmark v0.2.1 fixes the session-start memory snapshot on large stores and makes capture use project aliases.

## Fixes

- The session-start snapshot fetched the 500 newest approved conclusions across the whole store and then filtered them by project. In a store with thousands of conclusions the current project's facts were usually not among them, so the snapshot came back empty apart from a "[truncated]" line. Scoped conclusions are now fetched by tag, and a snapshot with nothing to show is left out.
- Capture now applies `project-aliases.json` from the store directory, so a session in a worktree or a renamed checkout is tagged with the project name its conclusions use. `pathmark dream` reads the same file. Edits to it are picked up without a restart.
- When `pathmark dream` replaces a conclusion, the replacement keeps the old one's `wiki:`, `wiki-private:` and `section:` tags, so approving it never changes where the fact is published.

## Verification

- New checks in `scripts/test-dream.mjs`: a project's fact appears in the snapshot with 600 newer conclusions from another project in the store, capture tags an aliased folder with the canonical project, and a replacement keeps its page tags.
- `scripts/test-codex-adapter.mjs` now expects no snapshot block when there are no approved conclusions.
- Full TypeScript build, runtime suite, memory-quality evaluation and ESLint.
