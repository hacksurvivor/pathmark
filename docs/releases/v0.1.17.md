# Pathmark v0.1.17

Pathmark v0.1.17 lets Claude Code run Pathmark's local read-only tools without a permission prompt.

## Why

Claude Code asks before every MCP tool call that is not on its allow list. In auto mode, each of those calls first goes to a server-side safety classifier; when the classifier errors, the call is blocked even though nothing is wrong with it. Pathmark's instructions ask agents to call `recall_memory` at the start of non-trivial tasks, so recall was the call most often held up. MCP `readOnlyHint` annotations, added in v0.1.16, do not exempt a tool from that check.

## Read-only allow rules

- `pathmark setup claude-code --apply-permissions` merges allow rules for the ten tools that only read the local store into `~/.claude/settings.json` (honoring `CLAUDE_CONFIG_DIR`): `get_config`, `search_memory`, `get_context`, `recall_memory`, `session_trace`, `list_conclusions`, `list_pending_conclusions`, `get_memory_snapshot`, `audit_memory`, and `doctor_memory`.
- The command is opt-in and conservative: it backs up an existing file, adds only missing rules, keeps every other key and the existing rule order and indentation, writes atomically, and refuses to change a file that is not valid JSON or whose `permissions.allow` is not an array. Re-running it is a no-op.
- `pathmark setup claude-code --json` also includes the same `permissions.allow` block for people who prefer to merge it by hand.
- Tools that write or delete memory, and `ask_memory`, `chat`, and `consolidate_memory` (which log recalls or may call an external synthesis provider), are never included and keep their prompts.

## Verification

- The allow list lives in one place and a wire-level test asserts it equals exactly the set of tools a real MCP client sees as `readOnlyHint: true` and `openWorldHint: false`, so a new or re-annotated tool cannot drift onto or off the list unnoticed.
- Tests cover creating a new settings file, merging into an existing one with other keys and a pre-existing rule, backup contents, indentation, idempotence, and refusal to touch invalid JSON without leaving temp or backup files behind.
- Full TypeScript build, runtime suite, memory-quality evaluation, ESLint, and coverage thresholds.
