# Pathmark v0.1.6

Pathmark v0.1.6 hardens multi-process storage and adds the lifecycle controls needed for a long-running local memory store.

## Highlights

- SQLite initialization and index synchronization now use a cross-process index lock. Busy or locked databases are no longer renamed as corrupt; only verified corruption errors enter the recovery path.
- MCP writes redact common secret-shaped values by default, with `PATHMARK_REDACT_MCP_WRITES=off` as an explicit opt-out.
- Every MCP read and write supports first-class namespace scoping, including `get_context`, `recall_memory`, `ask_memory`, and `chat`.
- New `update_memory` and `supersede_memory` tools preserve revision and replacement history.
- Expiration, retention, exact deduplication, diagnostics, compaction, backup, scoped export/import, and preview-first hard purge are available through MCP and CLI surfaces.
- Optional AES-256-GCM portable exports protect memory bundles in transit or backup when `PATHMARK_EXPORT_KEY` is configured.
- Optional hybrid reranking delegates candidate ordering to a local command through `PATHMARK_RERANK_COMMAND`, keeping the default dependency-light and lexical.
- Gemini CLI setup now includes automatic prompt, response, tool, and session recall hooks. Generic transcript ingestion supports other harness export formats.

## Safety

- `compact_memory` and `purge_memory` preview by default and require `confirm: true` to change the canonical store.
- `pathmark compact` and `pathmark purge` likewise require `--apply`.
- Applied compaction and purge operations create a point-in-time JSONL backup first.
- Hosted sync remains out of process. Pathmark provides scoped mergeable exports and imports without silently sending memory over the network.
