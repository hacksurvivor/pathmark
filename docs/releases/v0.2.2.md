# Pathmark v0.2.2

Pathmark v0.2.2 stops treating relayed messages as the user's own words.

## Why

Some messages reach the agent through the user channel even though nobody typed them: T3 Code tool messages, results of delegated tasks, task notifications, context handoffs, grokhost bot handoffs (`[From grokhost: ...]`), and harness envelopes such as `<heartbeat>`, `<task>` or `<in-app-browser-context>`. A pasted block (`<pasted_content>`) stays the user's own submission. Capture stored them with `role-user`, so `pathmark dream` could count an agent's report as something the user said. In the first real runs the separate verification step caught every case, but the trust boundary for auto-approval shouldn't rest on that step alone.

## Changes

- User turns of a `codex exec` session (session header `source: exec`) are all relayed: nobody types in those automation runs, and their prompts often open with image attachments, just like the user's own prompts in an interactive session, which stay theirs.
- Capture tags such messages `relayed` (they keep `role-user`, so session traces still show them in order).
- The `relayed` tag is left out of the dedupe key, so two copies of the same message captured before and after the upgrade still collapse into one.
- `pathmark dream` never counts a relayed message as the user's words for auto-approval. Older captures without the tag are recognised by their text. The model is told to weigh them like an agent's reply.

## Verification

- `scripts/test-dream.mjs`: a T3 relay prompt is tagged `relayed` at capture and the user's own prompt is not. A conclusion citing an untagged older delegate result stays pending even at confidence 0.97.
- Full TypeScript build, runtime suite, memory-quality evaluation and ESLint.
